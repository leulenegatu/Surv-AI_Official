# Public repository security audit

Prepared October 20, 2026. Scope: the current private development tree, its tracked files and all reachable local Git commits, followed by the independent public tree and release ZIP. This is release hygiene and focused automated/manual review, not an external penetration test or proof that every possible secret format is detected.

## Findings and disposition

| Area | Finding | Release treatment |
| --- | --- | --- |
| Git tracking/history | Six tracked files, one reachable commit, six historical file blobs inspected; no credential/private-runtime pattern findings | Original `.git` and history are excluded; no history rewrite or Git initialization performed |
| `.env` / provider configuration | Private environment and optional `.local-data/ai-provider.json` can contain an API key | Excluded completely; `.env.example` has an empty key |

No real credential was identified in reachable committed history by the scans/manual inspection performed, so no credential rotation/history remediation was triggered by this audit. If another branch, remote, deleted/unreachable object or older external backup contains a real credential, it remains outside this bounded history finding and must be assessed separately. Nothing in this report recommends publishing the parent development repository.

## Public tree policy

`github-public/` is a separately assembled source tree, not a copy of the private repository metadata. Runtime modules, frontend, companion, startup/setup files, tests and documentation are selected explicitly. Public release packaging is a public-tree extension of the existing deterministic source packager; the original packager and installation remain untouched.

`public-files.json` is the packaging allowlist. The verifier rejects private runtime paths, environment files other than the blank example, database/log/key/archive artifacts, symlinks, path traversal, broken local documentation links and known secret-shaped values. The clean-tree mode also rejects unreviewed files anywhere in the folder, including ignored runtime files. Pattern output reports **filenames and categories**, never secret values.

```powershell
python tools/verify_public.py --clean-tree
python tools/package_release.py
```

The second command packages only allowlisted source and a generated byte/hash manifest, even if the application has later created ignored runtime data. Do not upload an installation after using it merely because `.gitignore` exists. Prefer the reviewed ZIP or a fresh clean checkout. Release validation separately compares private known credential/control values in memory against candidate bytes without printing those values.

## Screenshot privacy

All documentation images come from an isolated synthetic installation; no screenshot was taken from the user's real workspace. Captures block external browser requests, reject provider calls and use a generated canvas rather than real camera media. Context controls do not collect the actual desktop/browser. Images are converted without EXIF and visually reviewed. [Provenance and exact capture controls](screenshots/README.md).

## Application boundary review

Local authentication/Argon2id, owned queries/files, CSRF checks, optional pairing, request validation and existing deletion/retention behavior are retained. The public copy changes module paths, removes private contact/runtime assumptions and adds packaging/docs/setup guidance. It does not weaken account security or bypass person gating. API credentials remain server-side. The plain service remains loopback-only, and there is no public hosting configuration.

## Publication decision

The final verification report records the actual clean-folder/ZIP checks. The intended publication unit is **only the contents of `github-public/`** or the reviewed source ZIP. Do not upload the parent project, its `.git` history, personal runtime directories or private audit/test work folder.

Remaining approvals/limits: project license selection and explicit publication approval are pending. No repository, push, remote release or startup-task change is part of this preparation. Paid provider access, a second physical Windows PC, real webcam combinations, long sleep/resume and external security/accessibility certification are not claimed as verified. The legacy default model's current deprecation status is documented rather than hidden.
